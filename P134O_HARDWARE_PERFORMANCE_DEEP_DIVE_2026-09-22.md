Base: `MD2GBA_P134O_UIALIGN_PERF_SOURCE_2026-09-22.zip`, not the older P134N source. The updated source archive and four-file patch accompany this handoff. No new GBA binary is claimed.

## Source changes on top of P134O

* `main_p85.c`: remove the ordinary Mode-4 software renderer and startup framebuffer clear. Every projected refusal and complex VDP state now uses the existing tile-based legacy hardware path. On a legacy commit error the pending commit is canceled and hardware state reset for retry without clearing accumulated VDP dirtiness. The separate fatal error screen is unchanged. **Caveat:** unsupported complex modes still show the old hardware viewport, which may remain 1:1 instead of fitted, and a persistent hardware refusal may leave a stale/blank image until a supported state appears. Hardware-only is not the same as guaranteed 240×160 fit in every VDP mode.
* `md2gba_gba_projected.c`: skip projected Plane-A sampling/hash/VRAM uploads for cells completely hidden by native UI. Avoid rescanning the profile during UI activation and scanning for UI candidates while an already active panel exists. Fix map queue ownership: a later native tile can replace an earlier queued clear, with proper slot-reference accounting. Suppression skips native A-high targets. This closes a real first-writer-wins hole, independently of P134O's already-correct native SAT cursor transform.
* `profiles/ps4/m4a/include/md2gba_projected_profile.h`: enumerate profile windows from the previous match in one viewport pass instead of restarting for each index; find the portrait once per UI scan. Preserve P134O's provisional 28..33-tile bottom dialogue rejection and incomplete-portrait/chrome hold. Verify `$55C` as the usual portrait top-left before trying every possible 6×6 origin; retain the general fallback for other arrangements.
* `md2gba_gba_projected.c`: the fixed Y-phase lookup shows phase 2 reads three source rows while phases 0, 1, 3 and 4 read only two. Fetch 4 name words rather than 6 in those four phases; exact pixel output and dependency tests pass. Under uniform phase distribution, this is 4.4 vs 6 source-name reads per output tile on average, a 26.7% reduction in **that operation**, not a measured FPS gain.
* Rebuild the active native UI pattern bloom when a name-table update changes panel tile IDs; otherwise a later pattern-only update can be incorrectly rejected by the stale bloom.

The modified P134O host projected-runtime oracle passes, including added checks that native interior pixels survive suppression, two-row versus three-row source footprints, SAT-only yields avoid queue-mask clearing, and enumerated portrait/window blocks match the old indexed API. The main loop passes host C syntax checking. The projected state remains 32,128 / 32,768 bytes in this check. No ARM build, FPS or screenshot result is claimed.

## Additional verified performance changes in this deeper pass

* `queue_reset` used to clear all `queue_cell_mask[4][32]` words (512 bytes) whenever a VDP epoch changed. A new `queue_mask_ready` byte defers that clear until the first actual map-cell write. SAT-only movement, palette fades and fine scroll with no map writes no longer touch this mask. The field walking test explicitly verifies zero queue-mask clears on a SAT-only yield. The projected-state struct remains 32,128 bytes due to existing alignment padding.
* `bg_cell_sources_dirty` formerly computed inverse X/Y source pixel coordinates for both tile endpoints, then shifted them to cells. The exact predecoded phase footprint gives two source columns for every X phase and two source rows for Y phases 0/1/3/4 (three for phase 2). It now computes the base cell once per axis and adjusts the bounds. An exhaustive arithmetic comparison over target tile coordinates -200..200 proved the old and new cell intervals equal, including negative camera positions. The 38,400-pixel projection oracle and dirty-cell tests pass.

These are projector-side CPU-operation reductions, not a measured ARM FPS gain. They intentionally leave all VDP epochs, guest timing and audio untouched.

## What to investigate next, in impact order

1. **Measure actual cost by workload.** Capture project-renderer status, full-rebuild reason, number of converted edge pairs, slot-hash probes/collisions, UI scan count, SAT-only OAM path frequency, queue writes, VBlank commit time and guest/audio cadence for standing, walking on/off tile boundary, menu open/idle, cursor movement, dialogue construction and room transitions. P134O's earlier ~22% microbenchmark improvement was only for the tile assembler; it did not establish game FPS.
2. **Camera edge-slot descriptor cache.** On every tile boundary, `queue_cell_pair` still assembles 64 high/low pixels and hashes slots. An exact cache keyed by plane, three-by-two source name words, projection X/Y phase and the source tile-pattern generation could reuse the target tile if its slot is still owned and its content generation valid. Keep generation invalidation exact and avoid pinning unbounded slots. P134O's projected staging arena has only 640 free bytes; any separate cache must be budgeted in overall EWRAM and linker output, not silently inserted into this structure. Do not alter guest cycles or audio scheduling to get FPS.
3. **Full rebuild triggers.** `prepare_incremental` still forces `full_rebuild` if a camera scroll changes with any active UI, if the UI signature/count changes, or when the projected origin jumps more than one cell. `try_transactional_rebuild` samples 31×21 cells for each of two planes (1,302 pairs), with a possible old/new 768-slot capacity failure and recovery rebuild. Instrument frequency first. To avoid an active-UI rebuild, update its target/suppression cells with camera motion while holding the panel stationary in screen coordinates; do not simply delete the rebuild guard.
4. **Generic no-panel scan.** If the PSIV profile sees no recognizable chrome, `scan_fixed_ui_panels` may still run its expensive generic 40×28 detector. The `BLOCKS_EXHAUSTIVE` macro currently short-circuits only when profile count/candidate is nonzero. Profile menu-free map animation before bypassing the generic detector; a blind bypass could miss a genuine nonstandard framed panel.
5. **Text quality.** P134O already fixes the transient large-then-shrunken wide dialogue geometry and the seven-row native SAT field-menu cursor. The final 34→30 dialogue fitting still maps 32 interior source tiles into 28 target tiles and drops horizontal glyph detail. Improve stable text by a deliberate glyph layout/reflow policy rather than vertical world minification. Also check hardware renderer switching on complex VDP states, which can still change the apparent screen scale. The battle red cursor is a Plane-A tile in the PSIV disassembly, while P134O's field-menu cursor path uses a small SAT marker; do not collapse those two cases.

## Broader performance inventory from current source

* **Source-mask growth:** `bg_source_mask` is intentionally monotone as the 31×21 world ring streams. After visiting many map areas it can report pattern dirtiness for tiles no longer visible, causing a bounded 1,302-cell bloom probe. Profile how often `projected_bg_patterns_dirty` is true with zero final `queue_cell_pair` calls. An exact resident tile-refcount mask would need extra memory and correct updates on every edge and full bank switch; do not clear the existing mask without rebuilding residency.
* **Sprite phase churn:** `stage_sprite_positions_only` correctly avoids pixel conversion for unchanged SAT geometry. It falls back to `stage_sprites` when height-quantization variant changes or an actor becomes visible/changes its packed OBJ offset; the latter runs two SAT passes and may repack affected sprite pixels. Count reason codes and `md2gba_projected_test_obj_builds` during walking before changing actor presentation or introducing another OBJ cache. Preserve the accepted 16×21 field-actor compromise and native UI cursor geometry.
* **Map dirty bloom:** `projected_dirty_map_bloom` still probes each 32-byte name-table block across a whole 32×32 or 64×64 plane when any map block is dirty (64 to 256 block checks per plane). It could enumerate set bits from `vram_dirty_tiles` within the plane's wrapped VRAM range instead, but implement only with equivalent wrapped-range semantics and benchmark on ARM7; the current bitset query already exits early for clean planes.
* **Window recognition without UI:** With the PSIV profile installed, an empty profile scan may fall into the generic framed-window detector over a 40×28 source viewport. This can cost extra on map-animated fields. Do not bypass it solely because the PSIV profile says `BLOCKS_EXHAUSTIVE`: the present conditional fallback can still recognize nonstandard chrome. Record its call count and recognized panels before specializing the profile.
* **Queue overflow/capacity:** A 512-map-write limit and 768 pattern slots can turn otherwise incremental work into a transactional rebuild or backdrop recovery. Count distinct overflow/capacity reasons, average map writes per VBlank and old/new slot-union high-water. Reducing pre-overlay work or making references exact may help more than speeding the normal 64-pixel sampler.
* **VDP write path already optimized:** `md2gba_bus.c` compares before marking changed VRAM, has bulk sequential transfer loops, and uses 32-byte dirty precision. Avoid broad speculative changes to its epoch, DMA or trace behavior; those are tied to 68000-visible state and presentation correctness.
